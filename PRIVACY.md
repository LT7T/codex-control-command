# Privacy

Codex Command and Control runs locally and does not include telemetry, analytics, advertising, or a remote service.

The control centre reads only the information required from the running Codex desktop host: recent task titles and states, saved project labels, the selected task's recent status, and Codex usage-limit metadata. To let the task picker continue beyond the host's 50-result limit, it also reads the local `session_index.jsonl` title index plus the first `session_meta` record from current session files. It keeps only task IDs, titles, update times, workspace paths, and whether a record belongs to a user task; archived tasks and delegated subagent sessions are excluded from the picker. The Advanced Stats page also reads file names, sizes, modification times, and archive locations for local Codex session records. For a largest-history entry missing from the recent-task list, it may ask the local Codex host to resolve that task's saved title and workspace; returned turn contents are discarded. Account identifiers returned by the host are discarded and are not shown in the interface.

Usage Intelligence streams local Codex JSONL session records and extracts only numeric or categorical metadata needed for analysis: token counters, model and reasoning settings, turn IDs and timestamps, context-window size, completion state, tool category/name/status/duration, file-change counts, compaction events, and root/delegated relationships. Reports never include prompt text, assistant text, hidden reasoning, command text, file paths, tool arguments, tool outputs, or account identifiers. Parsed reports are cached only in the running process and disappear when the server stops.

Prompt-size measurement from existing session messages is disabled by default. If `measurePromptSize` is enabled, text is used only long enough to count characters, words, UTF-8 bytes, and an explicitly labelled approximate token count; the text is not returned, cached, or written. A follow-up sent through the control centre records the same numeric size fields so it can later be matched to its turn, but the submitted prompt itself is still not written to a separate log.

When the user right-clicks a word in the follow-up editor, only that single word and the browser's language tag are sent to the loopback server. The word is checked by the local Windows Spell Checking API. Successful results may remain in the server's in-memory cache for up to ten minutes, with at most 500 entries, and disappear when the server stops. Spelling requests and suggestions are not written to disk and are not sent to a remote service.

Optional outcome annotations contain only the user's rating, accepted/not accepted state, correction state, short category and strategy labels, and review minutes. They are stored in `usage-annotations.json` inside the local installation. The privacy-safe command-line reporter reads this file and local session records and writes JSON only to standard output unless the user deliberately redirects it.

Local Codex task titles and paths are displayed only in the browser on the same computer. They are not sent to this repository or its maintainers.
